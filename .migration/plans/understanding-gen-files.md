# Are the `.gen.xml` Files Needed?

## Short Answer
**No — not for the running site.** The two `.gen.xml` files are intermediate migration artifacts, not part of the deployed Edge Delivery project. Nothing in the codebase loads, imports, or builds from them.

## Evidence Gathered

| Check | Result |
|-------|--------|
| Referenced in any `.js` (scripts, blocks, tools/importer) | No matches |
| Referenced in build config / `component-*.json` | No matches |
| Location | `migration-work/` — excluded via `.eslintignore` line 4 |
| CSS/transformer "matches" (columns-promo, doc-sections, etc.) | Coincidental — they contain the word "migration", not the files |

## What They Actually Are
- `migration-work/jcr-content/nav.gen.xml` — generated JCR XML for site navigation
- `migration-work/jcr-content/index.gen.xml` — generated JCR XML for the homepage
- The `.gen` suffix marks them as **regenerable output** of the xwalk migration tooling. They can be re-produced from source (cleaned HTML + parsers/transformers), so they are safe to delete and are not hand-maintained.

## When They *Would* Matter
- They are useful **during** an active migration as inputs to review or to upload to Document Authoring / AEM.
- Once content is uploaded/published (or if the migration is complete), they are just leftover scratch files.

## Recommendation
- Safe to leave in place (they are ignored by lint and don't ship to the site), **or** safe to delete if you want a clean tree — they can be regenerated by re-running the import tooling.
- Do **not** hand-edit them; edit the migration source and regenerate instead.
